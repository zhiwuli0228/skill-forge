## ADDED Requirements

### Requirement: Generated packages receive a quality report
The system SHALL construct a deterministic generation quality report for each non-interactive Skill package generated by `create`.

#### Scenario: Report includes validation status and score
- **WHEN** `skill-forge create "<requirement>"` generates a Skill package
- **THEN** the system SHALL validate the generated package
- **AND** the system SHALL produce a quality report containing validation status and a numeric score from 0 through 100

#### Scenario: Report includes validation issues
- **WHEN** post-generation validation returns errors or warnings
- **THEN** the quality report SHALL include those errors and warnings separately

#### Scenario: Report includes next actions
- **WHEN** a quality report is produced
- **THEN** it SHALL include deterministic next actions suitable for the validation result

### Requirement: Quality score is deterministic
The system SHALL calculate the quality score from structured validation results using stable penalties.

#### Scenario: Valid package without warnings receives full score
- **WHEN** validation returns no errors and no warnings
- **THEN** the quality score SHALL be 100

#### Scenario: Warnings reduce score without invalidating generation
- **WHEN** validation returns warnings and no errors
- **THEN** the quality score SHALL be reduced by a deterministic warning penalty
- **AND** the report status SHALL remain valid

#### Scenario: Errors reduce score and mark report invalid
- **WHEN** validation returns one or more errors
- **THEN** the quality score SHALL be reduced by a deterministic error penalty
- **AND** the report status SHALL be invalid

### Requirement: Quality report is covered by automated tests
The system SHALL include automated tests for quality report scoring and post-create presentation.

#### Scenario: Tests cover score construction
- **WHEN** the test suite runs
- **THEN** it SHALL verify score calculation for clean, warning, and error validation results

#### Scenario: Tests cover create report output
- **WHEN** the test suite runs
- **THEN** it SHALL verify that non-interactive `create` displays a quality report after generating a package
